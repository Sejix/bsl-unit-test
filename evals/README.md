# Проверка поведения навыка

[evals.json](evals.json) содержит задачи, исходные материалы и критерии результата.
Это набор сценариев для оценки агента, а не выполненные тесты платформы 1С.
Проверки текущего обновления и их ограничения: [результаты](validation.md).

## Порядок проверки

1. Подготовь изолированный рабочий каталог с нужной версией навыка и исходными
   материалами сценария. Соблюдай ограничения исходного проекта на средства работы.
2. Передай исполняющему агенту только `prompt`, `environment` и `source_files`.
   Ожидаемый ответ и критерии оставь оценивающей стороне. Для проверки автоматического
   выбора не называй навык в запросе; для явного вызова укажи его точный путь.
3. Сохрани созданные файлы, различия и сведения о выполненных проверках. Если нет
   платформы 1С или полной конфигурации, оцени материалы и ограничения отдельно;
   не объявляй тест выполненным по одному наличию кода.
4. Примени критерии `assertions` к наблюдаемому результату. Допускай равноценные
   решения и параметризованные тесты; не требуй буквального совпадения ответа,
   конкретного числа процедур или ненужного способа подмены.
5. Если доступна тестовая база, выполни затронутые тесты. Проверь, что существенное
   нарушение ожидаемого поведения вызывает ошибку проверки. Например, изменение
   формулы скидки должно обнаруживаться проверкой суммы, а не только проверкой типа.

Для ручного разбора достаточно таблицы: сценарий, использованная версия навыка,
результат каждого критерия, подтверждающие файлы, ограничения проверки.
Непроверенное отмечай отдельно от успешного и ошибочного результата.

## Сравнение версий

Сравнивай исходный и обновленный навык на одинаковых исходных материалах,
одинаковой модели и с одинаковыми возможностями окружения. Используй независимые
сеансы: вывод предыдущей версии не должен подсказывать ответ следующей.
Фиксируй выбранную модель, доступ к исходникам и наличие платформы.

Сначала проверь существенные случаи: чистое вычисление, новая зависимость,
готовый внутренний перехват, транзакция, запись базы, клиент и EDT, HTTP,
исправление падающей проверки. Затем проверь выбор навыка на посторонней задаче
и ограничение версии. Не делай вывод обо всех моделях по одному выполнению.

Локальная программа `scripts/validate.py` проверяет целостность материалов,
но не оценивает ответы агента. Сравнение поведения и фактическое выполнение
тестов в 1С остаются отдельными проверками.
