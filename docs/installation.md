# Установка и использование

`bsl-unit-test` распространяется как каталог в формате
[Agent Skills](https://agentskills.io/specification). `SKILL.md` находится
в корне репозитория. Копируйте каталог целиком: инструкции ссылаются на
`references/` и используют шаблоны из `assets/`.

## Выберите место установки

Каталог для навыков зависит от помощника. Установка в проект делает навык
доступным для этого проекта; установка в личный каталог — для разных проектов
этого пользователя.

| Помощник | В проекте | Для пользователя | Явный вызов |
|---|---|---|---|
| Codex | `.agents/skills/bsl-unit-test/` | `~/.agents/skills/bsl-unit-test/` | `$bsl-unit-test` |
| Claude Code | `.claude/skills/bsl-unit-test/` | `~/.claude/skills/bsl-unit-test/` | `/bsl-unit-test` |
| GitHub Copilot в VS Code | `.agents/skills/bsl-unit-test/` | Уточните в документации помощника | Выберите навык через `/skills` |
| Другой помощник с поддержкой Agent Skills | Его каталог навыков, подкаталог `bsl-unit-test/` | По документации помощника | По документации помощника |

`~` обозначает домашний каталог пользователя. В PowerShell для него удобно
использовать `$env:USERPROFILE`. Поддержка формата не означает одинаковые пути
и команды во всех помощниках.

Пути и способы вызова приведены по официальным руководствам
[Codex](https://developers.openai.com/codex/skills),
[Claude Code](https://code.claude.com/docs/en/skills) и
[примеру Agent Skills для VS Code](https://agentskills.io/skill-creation/quickstart).
Это примеры размещения, а не результаты проверки навыка во всех перечисленных средствах.

## Установка с Git

Нужен установленный Git и доступ к репозиторию. Для закрытого репозитория
войдите в учетную запись GitHub, которой предоставлен доступ.

Для **Codex или GitHub Copilot в VS Code**, из корня вашего проекта 1С:

```text
git clone https://github.com/Sejix/bsl-unit-test.git .agents/skills/bsl-unit-test
```

Для **Claude Code**, из корня вашего проекта 1С:

```text
git clone https://github.com/Sejix/bsl-unit-test.git .claude/skills/bsl-unit-test
```

Выберите одну команду для своего помощника. Если каталог уже существует,
сначала проверьте его содержимое: возможно, навык уже установлен.

Для установки в личный каталог в **PowerShell** выберите нужный вариант:

```powershell
git clone https://github.com/Sejix/bsl-unit-test.git "$env:USERPROFILE/.agents/skills/bsl-unit-test"
```

```powershell
git clone https://github.com/Sejix/bsl-unit-test.git "$env:USERPROFILE/.claude/skills/bsl-unit-test"
```

Первый вариант предназначен для Codex, второй — для Claude Code.
В **Linux или macOS** соответствующие команды:

```sh
git clone https://github.com/Sejix/bsl-unit-test.git "$HOME/.agents/skills/bsl-unit-test"
```

```sh
git clone https://github.com/Sejix/bsl-unit-test.git "$HOME/.claude/skills/bsl-unit-test"
```

Если навык устанавливается внутрь другого репозитория Git, эта команда создает
вложенный репозиторий для личной установки. Чтобы передать навык вместе с
проектом коллегам, удобнее скопировать файлы из архива и добавить их в репозиторий
проекта обычным способом.

## Установка без Git

1. Откройте [репозиторий](https://github.com/Sejix/bsl-unit-test), нажмите
   `Code` → `Download ZIP` и распакуйте архив.
2. Переименуйте распакованный каталог, например `bsl-unit-test-main`, в `bsl-unit-test`.
3. Перенесите его в каталог навыков выбранного помощника из таблицы выше.

Проверьте итоговое расположение: файл должен находиться непосредственно по пути
`<каталог-навыков>/bsl-unit-test/SKILL.md`, рядом с каталогами `references` и `assets`.
Дополнительного уровня вроде `bsl-unit-test/bsl-unit-test-main/SKILL.md` быть не должно.

Установка навыка не требует Python и не изменяет конфигурацию 1С.

## Первый вызов

Откройте свой проект 1С в помощнике и убедитесь, что он обнаружил `bsl-unit-test`.
В Codex и GitHub Copilot в VS Code проверьте список через `/skills`;
в Claude Code найдите `/bsl-unit-test` в меню команд.
Если навык не появился, начните новый сеанс помощника.

В Codex CLI или расширении редактора можно написать:

```text
$bsl-unit-test Покрой тестами метод Расчеты.СуммаСкидки в открытом проекте.
При сумме 100 и скидке 25 процентов ожидается 75.
```

В Claude Code:

```text
/bsl-unit-test Покрой тестами метод Расчеты.СуммаСкидки в открытом проекте.
При сумме 100 и скидке 25 процентов ожидается 75.
```

В другом помощнике выберите навык его средствами и передайте ту же задачу.
Имена модуля и метода здесь условные: замените их на существующие в своем проекте.
Укажите ожидаемое поведение, путь к исходникам и существующим тестам, если помощник
не может определить их самостоятельно.

Ожидаемый результат — тесты, необходимые изменения их регистрации и сведения
о проверках. Для фактического выполнения нужны платформа 1С, тестовая база
с YAxUnit и настроенный в проекте способ запуска. Навык не устанавливает их.

## Обновление и удаление

При установке через Git перейдите в установленный каталог `bsl-unit-test`:

```text
git status --short
git pull --ff-only
```

Если есть собственные изменения, сохраните их до обновления. Команда
`--ff-only` не создает слияние при расхождении истории; при ошибке разберите
причину перед повторным обновлением. Точную установленную версию можно узнать
командой `git rev-parse HEAD`.

При установке из архива скачайте новую версию и замените файлы навыка,
предварительно сохранив собственные изменения. После обновления проверьте
обнаружение навыка помощником. Чтобы удалить навык, удалите установленный
каталог `bsl-unit-test` из каталога навыков своего помощника.

## Если не получилось

| Признак | Что проверить |
|---|---|
| GitHub сообщает `404` или Git не скачивает репозиторий | Адрес, доступность репозитория и права текущей учетной записи |
| Помощник не видит навык | Каталог для вашего помощника, точное имя `bsl-unit-test`, расположение `SKILL.md`; затем новый сеанс |
| Помощник не находит справки или шаблоны | Установлен весь каталог, а не один `SKILL.md` |
| Навык выбран, но тесты не запускаются | Наличие YAxUnit и настройки запуска в целевом проекте 1С |
| Пример использует отсутствующий метод YAxUnit | Версию движка в проекте и [справку о совместимости](../references/compatibility.md) |

Если проблема остается, [сообщите об ошибке](../CONTRIBUTING.md).
