# Мокито: поведение зависимостей и вызовы

Источники: [Мокито](https://bia-technologies.github.io/yaxunit/docs/features/mocking/mockito/),
[принципы работы](https://bia-technologies.github.io/yaxunit/docs/features/mocking/mockito/how-to/).
Сигнатуры и ограничения сверены с [выпуском 25.12](compatibility.md).

## Предпосылка подмены

Для каждого подменяемого метода должен существовать подходящий перехватчик
`&Вместо` с `МокитоПерехват.АнализВызова`. Вызов `Обучение()` только настраивает
его поведение. Сначала найди перехватчик в тестовом расширении; если он уже есть,
используй его. Если отсутствует, подготовь его по [справке](interception.md).
Это одинаково важно для вызова другого модуля и вызова внутри того же модуля.

Неэкспортный метод нельзя напрямую вызвать из тестового общего модуля, но это
не запрещает перехват доступного для расширения метода. Проверяемое поведение
обычно вызывают через публичную точку входа, а внутреннюю зависимость подменяют.
Для методов платформы, внешних обработок и методов самих расширений не обещай
такой перехват: сначала проверь ограничения платформы и состав конфигурации.

## Обучение и сброс

Ниже `ПоставщикДанных` и `ЖурналОпераций` - условные модули проекта с уже
подготовленными перехватчиками указанных методов.

```bsl
Мокито.Обучение(ПоставщикДанных).Когда("ПолучитьЗначение").Вернуть(42);
Мокито.Обучение(ПоставщикДанных, Ложь).Когда("ПроверитьДоступ").Вернуть(Истина);
Мокито.Обучение(ЖурналОпераций).Когда("ЗаписатьСобытие").Пропустить();

Мокито.Прогон();
```

`Обучение(Объект)` по умолчанию забывает настройки **этого объекта**.
Повторное обучение того же объекта без `Ложь` потеряет предыдущие правила;
обучение другого объекта их не сбрасывает. Для нескольких методов одного
объекта можно продолжить цепочку `.Когда(...).Вернуть(...).Когда(...)`.

Доступные реакции: `Вернуть(...)`, `Пропустить()`, `ВыброситьИсключение(...)`,
`ВыполнитьМетод()`. `Наблюдать(...)` собирает вызовы, сохраняя реальное поведение.
Не используй наблюдение там, где требуется исключить запись или внешний запрос.
Если ни одно правило не подходит, перехватчик может продолжить реальный вызов.

## Условия по параметрам

Для явного выбора метода используй его имя и `Мокито.МассивПараметров(...)`.
Это не вызывает зависимость на этапе обучения.

```bsl
Условие = ЮТест.Предикат().Больше(0).Получить();
Мокито.Обучение(ПоставщикДанных)
	.Когда("ПолучитьЗначение", Мокито.МассивПараметров(Условие)).Вернуть(42);

Мокито.Прогон();
```

Для произвольного аргумента есть `Мокито.ЛюбойПараметр()`. Учитывай количество,
порядок аргументов и значимые значения по умолчанию. При нескольких правилах
проверь выбор реакции в используемой версии, а не полагайся только на порядок
строк обучения. Предикат сохраняй через `Получить()` до создания следующего.

## Проверка после выполнения

Перед вызовом проверяемого кода переведи Мокито в `Прогон()`. По умолчанию
этот вызов сбрасывает статистику; повторный прогон разделяет фазы наблюдения.
Проверку выполняй после нужного действия:

```bsl
Мокито.Проверить(ПоставщикДанных).КоличествоВызовов("ПолучитьЗначение").Равно(1);
Мокито.Проверить(ЖурналОпераций).КоличествоВызовов("ЗаписатьСобытие").Пусто();
```

Для проверки аргументов можно отфильтровать количество вызовов либо получить
статистику. Например, для метода с одним аргументом:

```bsl
Вызовы = Мокито.Проверить(ПоставщикДанных).Вызовы("ПолучитьЗначение");
ЮТест.ОжидаетЧто(Вызовы).ИмеетДлину(1);
ЮТест.ОжидаетЧто(Вызовы[0].Параметры[0]).Равно(5);
```

Статистика требует того же подготовленного перехвата, что и изменение поведения;
отдельного нового `&Вместо` только ради `Вызовы()` не нужно. Если вызовы пусты,
проверь точку входа, владельца метода, перехватчик, контекст, переход в прогон,
сброс статистики и условия отбора. Внутренний вызов сам по себе не доказывает причину.
