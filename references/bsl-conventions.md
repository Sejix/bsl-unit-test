# Описания методов и код общих модулей

## Описание метода

Опиши существенное для вызывающего кода поведение. У простого метода с очевидным
назначением комментарий можно опустить. Помести описание перед директивой
компиляции метода, отдели разделы пустой строкой комментария и укладывай строки
в 120 символов. В примере вызова экспортного метода укажи имя модуля.

Для структуры или таблицы значений найди метод, который формирует именно этот
состав данных. В описании параметра используй форму
`Параметры - см. Модуль.Метод`, для результата — `Структура - см. Модуль.Метод`.
Для коллекции укажи `Массив из см. Модуль.Метод`. Ссылка может вести и к объекту
метаданных, например к табличной части. Проверь каждую ссылку в исходниках.
Если подходящего конструктора нет, опиши фактический состав данных.

Внутри описания параметра помечай элементы списка знаком `+`, а вложенные
свойства структуры — знаком `*`. Для значения типа «общий модуль» указывай
`CommonModule.<ИмяМодуля>`.
[Правила описания методов YAxUnit](https://github.com/bia-technologies/yaxunit/blob/a2beee45e81ad1108db3f73aa892fbd7972c2ba6/.agents/skills/bsl-method-description/SKILL.md).

## Переменные и массивы

В общем модуле BSL объявление `Перем` на уровне модуля недопустимо. Оставляй
данные одного вызова локальными, передавай их между методами через параметры.
Для общего состояния нескольких обработчиков теста выбери контекст с подходящим
сроком жизни. См. [подготовку и очистку данных](lifecycle.md).

В коде YAxUnit для массива с заданными элементами используй, например,
`ЮТКоллекции.ЗначениеВМассиве("Первый", "Второй")`. В выпуске 25.12 метод
принимает от одного до десяти аргументов. У конструктора `Новый Массив`
числовые аргументы задают размеры измерений. Для пустого массива достаточно
`Новый Массив`. В прикладном проекте предварительно проверь доступность
метода коллекций в нужном контексте.
[Правила BSL в YAxUnit](https://github.com/bia-technologies/yaxunit/blob/a2beee45e81ad1108db3f73aa892fbd7972c2ba6/.agents/skills/bsl-syntax-pitfalls/SKILL.md).
