# Специальные тестовые данные без реальной ИБ

Используй эти приемы, когда метод требует платформенный объект, но сам тест не
должен ходить в реальные данные конфигурации.

Если нужен не ручной fixture, а builder или готовый эмулятор YAxUnit, сначала
прочитай `references/test-data-builders.md` и
`references/http-and-sql-stubs.md`.

## `ИнформацияОбОшибке`

Нельзя создать напрямую. Получай из реального исключения:

```bsl
ИнфОбОшибке = Неопределено;
Попытка
	ВызватьИсключение "Тестовая ошибка";
Исключение
	ИнфОбОшибке = ИнформацияОбОшибке();
КонецПопытки;
```

## `ВыборкаИзРезультатаЗапроса` без обращения к ИБ

```bsl
Данные = (Новый Запрос("ВЫБРАТЬ 1 КАК Поле")).Выполнить().Выбрать();
ПустыеДанные = (Новый Запрос("ВЫБРАТЬ 1 КАК Поле ГДЕ ЛОЖЬ")).Выполнить().Выбрать();
```

## Параметр по ссылке через `ТаблицаЗначений`

```bsl
Таблица = Новый ТаблицаЗначений;
Таблица.Колонки.Добавить("Значение");
Строка = Таблица.Добавить();
Строка.Значение = "Первая";
Данные = Таблица;
```

После вызова проверяй, что `Данные` сменили тип, например на
`СтрокаТаблицыЗначений`.

## Набор записей только в памяти

Если метод лишь наполняет набор записей и не вызывает `.Записать()`, создавай
реальный набор и проверяй его содержимое после вызова. Не объявляй метод
интеграционным раньше времени.

## Минимальная структура вместо фабрики, читающей ИБ

```bsl
Функция НовыйМинимальныйКонтекст()
	Контекст = Новый Структура;
	Контекст.Вставить("ТипИсходящее", Перечисления.ИПНаправленияПотоков.Исходящее);
	Возврат Контекст;
КонецФункции
```

Если фабричный метод сам делает запросы к ИБ, не вызывай его в тесте. Собери
только те поля, которые реально нужны тестируемому методу.

## Когда ручной fixture лучше builder

- Нужно 1-2 поля для чистой логики.
- Нужен объект только для чтения свойств, без записи в ИБ.
- Самодельная `Структура` или `ТаблицаЗначений` короче и понятнее builder-а.
