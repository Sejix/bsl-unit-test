# Создание данных средствами YAxUnit

Источники: [тестовые данные](https://bia-technologies.github.io/yaxunit/docs/features/test-data/),
`ЮТТестовыеДанные` и `ЮТКонструкторТестовыхДанных` [проверенного выпуска](compatibility.md).

Используй публичную точку входа `ЮТест.Данные()`. Перед собственной фабрикой
проверь существующие конструкторы и фабрики проекта. Если достаточно нескольких
полей структуры, создание реального объекта базы не требуется.

## Выбор средства

| Потребность | Средство и ограничения |
|---|---|
| Ссылка на записанный элемент, документ или группу | `СоздатьЭлемент`, `СоздатьДокумент`, `СоздатьГруппу` создают записи; нужна очистка |
| Записанный объект с контролируемыми полями и табличными частями | `КонструкторОбъекта(Менеджер)` |
| Движения документа по определенному регистру | `КонструкторДвижений(Документ, ИмяРегистра)` |
| XDTO | `КонструкторОбъектаXDTO(ИмяТипа, ПространствоИмен, Фабрика)`; проверь контекст и доступность схемы |
| Временный файл | `НовыйФайл`, `НовоеИмяВременногоФайла`; учти удаление |
| Незначимые дополнительные значения | Генераторы и `Подражатель()`; значимые ожидания задавай явно |

Если нужна только ссылка подходящего типа без существования записи, проверь
средства проекта и менеджера метаданных. Не создавай элемент базы автоматически
ради проверки одного типа. Пустая ссылка не заменяет непустую, если это
существенно для проверяемой ветви.

## Конструктор объекта

Пример предполагает существующий в конфигурации справочник `Товары`
с реквизитом `Артикул`. Значения и имена нужно подтвердить в проекте.

```bsl
Ссылка = ЮТест.Данные().КонструкторОбъекта("Справочники.Товары")
	.Установить("Наименование", "Тестовый товар")
	.Установить("Артикул", ТестовыйАртикул)
	.Записать();
```

`КонструкторОбъекта` возвращает конструктор. `Записать()` по умолчанию возвращает
ссылку; для объекта сверь параметр `ВернутьОбъект`. `Провести()` записывает
документ с проведением. Учитывай влияние обработчиков и параметров записи:
создание данных не должно скрыть проверяемое поведение.

`ТабличнаяЧасть(...)`, `ДобавитьСтроку(...)` и `Установить(...)` помогают заполнить
строки; `Объект()` возвращает выбор к объекту конструктора. Это интерфейс
конструктора, его не следует путать с одноименным методом утверждений.

`Фикция`, `ФикцияРеквизитов`, `ФикцияОбязательныхПолей` заполняют несущественные
данные. Они могут создавать связанные записи уже при заполнении реквизитов,
поэтому отсутствие завершающего `Записать()` не доказывает отсутствие записей.
Ключевые для теста значения задавай явно, случайные данные не должны менять
выбор проверяемой ветви. Для поиска собственного элемента подходит
`УникальнаяСтрока(...)` с последующей адресной проверкой.

Перед заполнением реквизита подтверди его тип, длину и допустимые значения
в метаданных или фабрике проекта. Уникальная строка не обязана помещаться
в произвольный реквизит; усечение может разрушить уникальность. Если метаданные
не предоставлены, обозначь предпосылку примера и необходимую проверку.
Не добавляй неподтвержденное обращение к метаданным вместо такой проверки.

## Контекст и очистка

Строковое имя менеджера позволяет не передавать недоступный клиенту объект
менеджера; это не делает все последующие методы доступными в любом контексте.
Проверяй директивы и сериализуемость параметров. Для XDTO при необходимости
объяви файловую зависимость фабрики при [регистрации](registration.md).

До записи выбери [стратегию изоляции](lifecycle.md). Автоматическое удаление
созданных данных и откат изменения существующих данных - разные механизмы.
