# Применение шаблонов

Шаблоны - заготовки для **XML-выгрузки Конфигуратора**, а не универсальный формат
метаданных. Для EDT изменяй `.mdo` и состав проекта принятыми средствами;
не создавай рядом `Configuration.xml` ради применения этого шаблона.
Сначала найди тестовый общий модуль, соответствующий проверяемому модулю, и проверь
возможность дополнить его. Выбор модуля и имени описан в [регистрации](registration.md).

## Новый тестовый модуль

- [Тело модуля](../assets/test-common-module.bsl.template).
- [Метаданные XML](../assets/test-common-module.xml.template).

| Поле | Значение |
|---|---|
| `TEST_MODULE_NAME` | Имя по соглашению проекта, при его отсутствии — по схеме YAxUnit из [регистрации](registration.md) |
| `TARGET_MODULE_NAME` | Проверяемый модуль или объект для описания |
| `TEST_NAME` | Имя экспортной тестовой процедуры |
| `TEST_BODY` | Подготовка, вызов и содержательные проверки с отступами |
| `REGISTER_METHOD` | `ДобавитьТест`, `ДобавитьСерверныйТест` или `ДобавитьКлиентскийТест` |
| `UUID` | Новый идентификатор метаданных |
| `XML_VERSION` | Версия формата из совместимого соседнего XML проекта |
| `CLIENT_MANAGED_APPLICATION`, `SERVER`, `CLIENT_ORDINARY_APPLICATION` | `true` или `false` по выбранным контекстам |

`TEST_BODY` замени настоящим кодом, не оставляй комментарии вместо проверки.
При смешанном контексте адаптируй тело к доступности кода и типов.
Правила [регистрации](registration.md) обязательны и для созданного по шаблону модуля.

В XML-выгрузке файлы обычно размещаются как `CommonModules/<Имя>.xml` и
`CommonModules/<Имя>/Ext/Module.bsl` относительно обнаруженного корня расширения.
Добавь модуль в `ChildObjects` его `Configuration.xml`; другие учетные файлы
обновляй по правилам проекта и средства выгрузки. Не заменяй существующий состав.

## Заимствование и перехват

- [Описание заимствованного общего модуля](../assets/adopted-common-module.xml.template).
- [Перехват процедуры](../assets/instead-stub.bsl.template).
- [Перехват функции](../assets/instead-function.bsl.template).

| Поле | Значение |
|---|---|
| `UUID` | Новый UUID объекта расширения, только при первом заимствовании |
| `XML_VERSION` | Совместимая версия XML проекта |
| `MODULE_NAME` | Имя заимствованного общего модуля |
| `EXTENDED_CONFIGURATION_OBJECT_UUID` | UUID исходного объекта конфигурации |
| `GLOBAL`, `CLIENT_MANAGED_APPLICATION`, `SERVER`, `EXTERNAL_CONNECTION` | Фактические свойства исходного модуля |
| `CLIENT_ORDINARY_APPLICATION`, `SERVER_CALL`, `PRIVILEGED`, `RETURN_VALUES_REUSE` | Остальные свойства исходного модуля |
| `METHOD_NAME`, `STUB_NAME` | Имя исходного метода и уникальное имя перехватчика |
| `METHOD_DOCUMENTATION` | Описание перехватчика с фактическими параметрами и результатом |
| `SIGNATURE` | Параметры с `Знач` и значениями по умолчанию |
| `PARAMETERS_ARRAY_EXPRESSION` | `Мокито.МассивПараметров(...)` или `Новый Массив` без параметров |
| `OWNER_EXPRESSION` | Владелец метода по [правилам перехвата](interception.md) |
| `FORWARD_ARGS` | Те же аргументы для `ПродолжитьВызов(...)` |

XML-шаблон относится только к общему модулю. Для объекта, менеджера или набора
записей заимствуй соответствующий объект, не создавай общий модуль вместо него.
Не перезаписывай существующий UUID и не удаляй уже имеющиеся перехватчики.
Проверь корректность идентификации объекта средствами проекта, если состав
метаданных отличается от заготовки.

UUID можно получить через `[guid]::NewGuid()` в PowerShell или `uuid.uuid4()`
в Python. После подстановки проверь остаточные `{{...}}`, синтаксис XML,
сигнатуру и возврат функции. Приведи отступы и переносы к правилам проекта:
размер обозначения в шаблоне не определяет длину строки готового кода.
Затем выполни доступные сборку и запуск в 1С.
