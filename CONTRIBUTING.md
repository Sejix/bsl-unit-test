# Участие в развитии

Можно предложить исправление инструкции, пример, новый проверочный сценарий
или улучшение шаблона. Перед началом прочитайте [README.md](README.md)
и [SKILL.md](SKILL.md), чтобы учесть назначение навыка.

## Сообщить о проблеме

Создайте [задачу на GitHub](https://github.com/Sejix/bsl-unit-test/issues).
Укажите:

- помощника, его версию и операционную систему;
- способ установки и версию навыка, если она известна;
- версию YAxUnit и формат исходников проекта;
- запрос, ожидаемый результат и фактически полученный результат;
- минимальный пример или ссылку на ошибочный фрагмент инструкции;
- выполнялся ли тест в 1С или проблема найдена при чтении кода.

Для ошибки установки сведения о YAxUnit и запуске тестов не нужны.
Примеры должны воспроизводить проблему без закрытых данных и учетных сведений.

## Предложить изменение

1. Для стороннего участия создайте свою копию репозитория средствами GitHub
   и отдельную ветку с изменением.
2. Основные правила помещайте в `SKILL.md`, подробности конкретной задачи —
   в `references/`, заготовки выходных файлов — в `assets/`.
   Не дублируйте справки в основном файле.
3. Подтверждайте методы YAxUnit по исходникам нужной версии. Если исправление
   касается поведения помощника, добавьте подходящий сценарий в `evals/evals.json`
   и оцените результат по [порядку проверки](evals/README.md).
4. Выполните проверки ниже и откройте запрос на слияние. Опишите проблему,
   изменение поведения, выполненные проверки и их ограничения.

Сохраняйте русскоязычные пояснения, существующее оформление примеров и табуляцию
пустых строк в BSL. Не переформатируйте посторонние участки.

## Проверить материалы

Из корня репозитория, Python 3.9 или новее, без дополнительных пакетов:

```text
python -X utf8 scripts/validate.py
```

При наличии исходников YAxUnit можно дополнительно проверить наличие прямых
вызовов и конструкторов данных из примеров:

```text
python -X utf8 scripts/validate.py --yaxunit-src <каталог-исходников-движка>
```

Передайте каталог с `CommonModules` и `DataProcessors`, например `exts/yaxunit/src`.
Эта проверка не подтверждает параметры методов, цепочки вызовов и контексты.

## Проверить формат Agent Skills

Используется [skills-ref](https://github.com/agentskills/agentskills/blob/main/skills-ref/README.md),
на который ссылается [спецификация Agent Skills](https://agentskills.io/specification).
Это справочное средство проверки формата, а не оценка качества инструкций.
Нужны Git и Python 3.11 или новее. Версия исходников средства закреплена
в [requirements-dev.txt](requirements-dev.txt).

В PowerShell:

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements-dev.txt
$env:PYTHONUTF8 = '1'
.venv/Scripts/skills-ref.exe validate "$PWD"
```

В Linux или macOS:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
PYTHONUTF8=1 .venv/bin/skills-ref validate "$PWD"
```

Имя каталога репозитория должно быть `bsl-unit-test`: средство сверяет его
с полем `name` в `SKILL.md`. Зависимости устанавливаются только в `.venv`.
Режим `PYTHONUTF8` нужен для чтения русскоязычных файлов независимо от настроек системы.
Полный путь через `$PWD` нужен из-за обработки пути `.` в закрепленной версии `skills-ref`.

[Проверка GitHub Actions](.github/workflows/validate.yml) выполняет обе программы
при отправке изменений и в запросах на слияние. Запуск на платформе 1С
и оценка ответов помощника выполняются отдельно. Фиксируйте их фактический
результат, не выдавая наличие сценариев за успешное выполнение.
